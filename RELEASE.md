# The Chronicles of Inotia: Legend of Feanor (PS Vita) — Release v0.1.0

First public build of the native iOS → PS Vita port of *Inotia: Legend of Feanor* (iOS 1.0.4). A custom Mach-O loader runs the original iPhone OS 2.2 ARMv6 executable; on physical hardware the game plays its intro video, reaches the title screen and menus, and is playable in-game.

## 📦 Release Package Contents

1. **`feanor.vpk`** (`PSVFEANOR`, version `01.00`): the Mach-O loader with its Foundation / UIKit / CoreGraphics / AudioToolbox / OpenAL / MediaPlayer replacements, vitaGL presentation, FreeType text (NanumGothic + DejaVu Sans fallback), FFmpeg intro video player and LiveArea.
2. **`rebase.bin`**: relocation table of 6,279 absolute 32-bit pointers for the 1.0.4 `feanor2i` executable.
3. **`binds.bin`**: 314 import slots that point into Apple frameworks, resolved by the loader at startup.

No game code or assets are included.

---

## 🛠️ What are `rebase.bin` and `binds.bin`?

`feanor2i` is a non-PIE `MH_EXECUTE` binary linked at `0x00001000`. The PS Vita does not let userland map that low, so the loader moves the whole image up by `MACHO_SLIDE = 0x98000000`. App Store builds of that era carry no local relocations, so every absolute pointer in the code's literal pools and in `__DATA` has to be found and slid by hand.

- **`rebase.bin`**: `'RBS1'`, `u32 count`, then `count × u32 vmaddr` of words that hold an absolute address (`+ MACHO_SLIDE`).
- **`binds.bin`**: `'BND1'`, `u32 count`, then `count × {u32 vmaddr, u32 addend, u8 lazy, char name[]}` for each slot bound to an external symbol.

Both are generated by `tools/ios_prep.py`. It rebuilds the pointers from the Objective-C metadata, `__cfstring` and `__mod_init_func`, from a recursive ARM/Thumb disassembly of the code (capstone), and from data heuristics. Anything doubtful goes to `report.txt`.

```bash
python3 -I tools/ios_prep.py ux0_data/feanor/game_app/feanor2i ux0_data/feanor
# or the whole pipeline (also Info.plist, nibs, intro video):
tools/stage_feanor.sh
```

## 🚀 Player Installation Guide

1. **PS Vita requirements**:
   * Custom Firmware (Enso 3.60 / 3.65 recommended).
   * `kubridge.skprx` under `*KERNEL` in `ur0:tai/config.txt`.
   * `libshacccg.suprx` in `ur0:data/` (obtainable via ShaRKBR33D).
2. **Game data**: extract `Payload/feanor2i.app/` from your decrypted 1.0.4 `.ipa` and stage it with `tools/stage_feanor.sh` (macOS, Python 3 and `ffmpeg`). Staging is still needed even with the attached tables: it converts `Info.plist` to binary and the H.264 intro video to MPEG-4 Part 2. Then copy `ux0_data/feanor/` to `ux0:data/feanor/`:
   ```text
   ux0:data/feanor/
   ├── game_app/        (feanor2i.app contents)
   ├── rebase.bin
   ├── binds.bin
   ├── nib.txt, nibs/
   ├── Feanor2i.mp4     (converted intro video)
   ├── controls.txt
   ├── font.ttf, font_latin.ttf
   ├── Documents/       (created automatically: saves)
   └── logs/            (created automatically: feanor_NNN.log)
   ```
3. **Install** `feanor.vpk` with VitaShell.

## 📋 Changelog (v0.1.0)

* **Colors**: the software-rendered view was read as A R G B bytes, but the iPhone's UIKit backing store is native `0xAARRGGBB` (`ByteOrder32Little`). Converting it correctly removed the green tint.
* **Crash when saving**: `NSData dataWithBytesNoCopy:length:` freed a buffer that still belonged to the game (`MC_fsWrite`). The buffer is no longer owned by the `NSData`.
* **Crash in gameplay**: the game keeps `UIFont fontWithName:size:` results without retaining them, and they were freed by the autorelease pool. Fonts are now immortal and cached per size, as on iOS.
* **Accented text**: NanumGothic has no Latin-1 accents. A DejaVu Sans Latin subset (`font_latin.ttf`) is used as a per-glyph fallback, and Spanish text now displays complete.
* **Frame rate**:
  * The run loop slept a full timer interval after running the callbacks, so each frame took 50 ms plus the work time. It now subtracts the work time.
  * The WIPI engine schedules each frame 10 ms after the previous one, but its timers were only checked every 50 ms. Frames that ran long were pushed back to 100 ms (10 FPS). The game's `CFRunLoopTimer` now runs every 4 ms.
* **Intro video**: added an FFmpeg software player (`video-ffmpeg` recipe). The H.264 video is converted to MPEG-4 Part 2 at staging time, and the frame is drawn with the same GL state as the game's presentation (no `glPushMatrix`, which overflows vitaGL's matrix stack in this port).
* **Music cuts**: the AudioQueue thread shared the main thread's priority. It now runs at priority 64 on its own core.
* **Pause**: Start / Select call the game's own suspend and resume handlers.
* **LiveArea**: built from the original game icon and title screen.

## ⚠️ Known Issues

- **Side bars**: the 3:2 image is shown at its original aspect (816×544) with black bars left and right.
- **Touch in menus**: some menu taps may need to be repeated.
- **Missing in-game elements**: some HUD/in-game elements may not be drawn yet.
- **Not yet verified on console**:
  * Pause with Start / Select.
  * The music-cut fix.
  * Saving after the `NSData` fix.
- **Online features** (Com2uS services, "More Games", purchases) are not available.
